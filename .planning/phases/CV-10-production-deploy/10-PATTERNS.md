## Pattern Assignments

### `backend/app/main.py` - add `GET /health/db` (route, request-response)

**Analogs:** `main.py` lines 206-208 (health route) and `backend/app/api/v1/frete.py` lines 1-14 (limiter usage).

**Existing health route** (main.py 206-208). New route goes directly below it:
```python
@app.get("/")
async def health():
    return {"status": "ok"}
```

**Imports already present in main.py** (lines 5-7, 30): `Request`, `JSONResponse`, `logger = logging.getLogger(__name__)` (line 37), and `from app.core.ratelimit import limiter, rate_limit_handler`. Only add the DB client import. Existing code imports it lazily inside a function (line 81: `from app.core.database import supabase`). For a testable `app.main.supabase` mock, add a top-level `from app.core.database import supabase`. Either import style is fine, but the test must patch whichever is used.

**Limiter pattern** (frete.py 10-14): the `request: Request` parameter is mandatory, decorator order is route first, then limiter, with a sync `def`:
```python
@router.post("/cotacao", response_model=CotacaoFreteResponse)
@limiter.limit("20/minute")
def post_cotacao(request: Request, body: CotacaoFreteRequest):
```

**Error handling pattern** (main.py 171-178): the global handler only maps `APIError` to 503 and re-raises everything else, so `/health/db` needs its own try/except. Mirror the existing generic body style:
```python
return JSONResponse(status_code=503, content={"detail": "Serviço temporariamente indisponível"})
```
RESEARCH uses `{"status": "error"}`; pick one. Keep it generic with no exception text. `logger.warning(..., exc_info=True)` matches the existing logging (line 176).

**Target (from RESEARCH Pattern 2):**
```python
@app.get("/health/db")
@limiter.limit("30/minute")
def health_db(request: Request):
    try:
        supabase.table("aromas").select("id").limit(1).execute()
    except Exception:
        logger.warning("health/db failed", exc_info=True)
        return JSONResponse(status_code=503, content={"status": "error"})
    return {"status": "ok"}
```
Note: `app.include_router(api_router)` has prefix `/api`. `/health/db` is mounted directly on `app`, so it is NOT under `/api`. Smoke script and UptimeRobot must use `$API/health/db`. Verify `aromas.id` exists in `backend/schema.sql` (~line 25).

### `backend/tests/test_health.py` (test, request-response)

**Analog:** `backend/tests/test_roles.py` lines 7-13 (env bootstrap before any `app.*` import; the root `conftest.py` also does `os.environ.setdefault` for `SUPABASE_URL`, `SUPABASE_KEY`, `ENVIRONMENT`).
```python
import os

os.environ.setdefault("SUPABASE_URL", "https://test-project.supabase.co")
os.environ.setdefault("SUPABASE_KEY", "test-service-role-key-for-unit-tests-only")
os.environ.setdefault("ENVIRONMENT", "development")

from app.core.roles import ROLE_ADMIN, ROLE_CUSTOMER, ROLE_STAFF, role_at_least
```
Class-grouped tests, plain `assert` (test_roles.py 16-25: `class TestRoleAtLeast:` / `def test_...(self):`). No existing test uses `TestClient`; this is the first. Use `fastapi.testclient.TestClient(app)` with `unittest.mock.patch("app.main.supabase")`. Cases: ok returns 200 `{"status":"ok"}`; `.execute` raising returns 503 with no exception text in the body; response carries no data. Rate-limit test is optional (in-memory limiter, may need reset between tests). Importing `app.main` triggers lifespan only inside `with TestClient(...)`. Plain `TestClient(app)` without a context manager avoids starting the background loops.

CI runs `uv run pytest tests/ -q` and `uv run ruff check app` (ci.yml 54-58), so keep both green.

**Analog:** itself (lines 7-44) and `ci.yml`. The workflow name in `ci.yml` is `name: CI` (line 1), which `workflow_run.workflows` must match exactly. CI triggers (ci.yml 3-6): `push: branches: [main]` and `pull_request`, hence the `event == 'push'` guard is required.

**Keep unchanged:** bun setup, `bun install --frozen-lockfile`, the `VITE_API_URL` fail-fast step (lines 26-32), build env (lines 34-39), deploy step with `CLOUDFLARE_API_TOKEN` (41-44), and `defaults.run.working-directory: frontend`.

**Change** (lines 9-10 and the checkout step line 19), per RESEARCH Pattern 3:
```yaml
on:
  workflow_dispatch:
  workflow_run:
    workflows: ["CI"]
    types: [completed]
    branches: [main]
jobs:
  deploy:
    if: ${{ github.event_name == 'workflow_dispatch' || (github.event.workflow_run.conclusion == 'success' && github.event.workflow_run.event == 'push') }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.workflow_run.head_sha || github.sha }}
```
Update the header comment (lines 3-6), which currently says to add `push:` later. Per D-22, ship `workflow_dispatch` only first, run it, smoke test, then add the `workflow_run` trigger in a follow-up commit.

## Shared Patterns

### Rate limiting
**Source:** `backend/app/core/ratelimit.py` (`limiter`, `rate_limit_handler`; registered in `main.py` lines 167-168). **Apply to:** `/health/db`. Decorate with `@limiter.limit("N/minute")` and always include `request: Request`. Limiter is in-memory and per-instance (single Render instance is correct). Client IP uses right-to-left hops via `RATE_LIMIT_TRUSTED_PROXY_HOPS` (set `1` on Render, provisional; verify XFF after the first deploy, Pitfall 2). Do not add `--forwarded-allow-ips="*"` to the Dockerfile CMD.

### Logging
**Source:** `main.py` line 37 `logger = logging.getLogger(__name__)`; usage lines 49, 176. Portuguese messages for loops, `logger.warning`/`exception` with no secrets.

### Env/config guard
**Source:** `backend/app/core/config.py`. `ENVIRONMENT=production` activates the wildcard-CORS guard; `ENABLE_API_DOCS` stays unset on Render. Features degrade without MP, Melhor Envio and Brevo credentials, so Render needs only the Supabase and core vars. With MP disabled, only the LGPD loop runs (main.py 145-148).

### Security headers (API)
**Source:** `backend/app/core/securityheaders.py` lines 3-9. Applies to every response, including `/health/db`. The smoke script can assert these on the API.

### CI gating
**Source:** `.github/workflows/ci.yml` (jobs `frontend`, `backend`; `name: CI`). Render "After CI checks pass" and the frontend `workflow_run` both depend on CI running on every push to `main` (do not path-filter it, Pitfall 9).

### Destructive-op safety
**Source:** `scripts/backup_db.sh` (encrypted dump via age/gpg, rotation, schemas `public` + `auth`); `.gitignore` already ignores `backups/` and `.env`. Apply to the cleanup SQL: rotate the DB password first (D-30), take a backup, restore-test it into Local Supabase, then run cleanup in a `BEGIN; ... ROLLBACK/COMMIT` transaction, show row counts, exclude Fernando's `auth.users` id (cascade to `user_roles`), and reset `produtos.estoque`. Human-confirmed only.
